# EasyBridge V2.9 — что здесь и что с этим делать

Собрано 2026-08-28 на ноутбуке. Архив нужен, чтобы продолжить работу на
домашнем ПК, где лежит Android-приложение EasyLink.

## Что внутри

```
lorabridge/            прошивка ESP-IDF (исходники, без build-каталогов)
serverchik-lorachat/   веб-часть: только модуль LoRa-чата, без сайта
EasyLink/              Android-приложение (исходники, без build и APK)
```

Сборочных каталогов нет намеренно: они весят 1.6 ГБ и пересобираются
одной командой. Готовых образов во `flasher/web/images/` тоже нет — те,
что лежали, были от V2.8, и страница прошивки залила бы старую
прошивку. Пересобрать: `tools/flasher/build_images.sh`.

Серверной части здесь ровно столько, чтобы **поднять её локально и
разрабатывать против неё приложение**. Ни `app.py`, ни базы, ни ключей
сайта в архиве нет.

## Состояние

| Часть | Готово | Проверено на железе |
|---|---|---|
| Конфигурируемое железо (hwcfg) | да | **нет** |
| Веб-мост: сообщения, медиа | да | **нет** |
| Звонки веб + FSK | да (сервер и прошивка) | **нет** |
| Автономные устройства | да | **нет** |
| Android: мост в веб | да | **нет** |

Прошивка собирается на четыре платы. Серверная часть покрыта 106
тестами. На живом железе не проверялось ничего из V2.9.

## Главное, что нужно сделать

**Проверить всё на живом железе.** Код собирается и покрыт тестами, но
ни одна часть V2.9 не работала на настоящих платах и телефонах. Порядок
проверки — в конце `lorabridge/TODO.MD`, начинать стоит с самого
скучного пункта: загрузки с пустым NVS на знакомой плате.

В приложении мост уже написан (`net/WebClient.kt`, `repo/WebRepo.kt`,
`audio/WebAudioBridge.kt`, экран в Настройки → Веб-чат). Что осталось
доделать — перечислено в конце `lorabridge/docs/WEB_BRIDGE.md`:
загрузка медиа в веб, экран виджетов датчиков на телефоне и адресная
доставка вместо широковещательной.

## Собрать и проверить всё разом

```bash
cd lorabridge
./build_all.sh
```

Обходит все три части: прошивку на четыре платы, приложение и тесты
веб-части, в конце показывает сводку. Занимает около полминуты.
Каталоги ищет по умолчанию рядом (`~/AndroidStudioProjects/EasyLink`,
`~/serverchik`) — если на этой машине они лежат иначе, задайте
`EASYLINK_DIR` и `SERVERCHIK_DIR`. Путь к ESP-IDF — `IDF_EXPORT`.

Ничего никуда не выкладывает: деплой — отдельное действие.

Отдельные части: `./build_all.sh fw`, `app`, `server`.

## Как поднять сервер локально

```bash
cd serverchik-lorachat
python lorachat_dev.py --seed        # http://127.0.0.1:5055/lora-chat/
```

`--seed` заводит тестовую сеть с участниками Philip / Misha / Roma
(пароль `test1234`) — та самая тройка из сценария «двое в вебе, третий
в эфире». Скрипт напечатает персональные ссылки. Логин хоста —
`/login` (заглушка, настоящий сайт логинит сам).

Прогнать тесты: `./run_lorachat_tests.sh` — создаст своё окружение и
ничего системного не тронет.

## Собрать что-то одно

```bash
cd EasyLink && ./gradlew :app:assembleDebug     # APK
```

`local.properties` в архив не положен — Android Studio создаст свой с
путём к вашему SDK.

```bash
cd lorabridge
source ~/esp/esp-idf-v5.5.1/export.sh
idf.py -B build_t3_v161 -DSDKCONFIG=build_t3_v161/sdkconfig \
    -DSDKCONFIG_DEFAULTS="sdkconfig.defaults;sdkconfig.board_t3_v161" \
    -DIDF_TARGET=esp32 build
```

## Чего в V2.9 сознательно нет

- **Скриптов виджетов в эфире.** Изначально задумывалось, что скрипт
  едет вместе с пакетом датчика. Это удалённое исполнение кода: пакет
  неподписан, отправителя не проверить, а код выполнился бы у всех, кто
  услышал. Вместо этого — безопасные выражения на сервере. Подробно и с
  обоснованием: `docs/DEVICES.md`.
- **Драйверов SX1280 (2.4 ГГц) и HaLow.** Профили и заглушки есть,
  устройство с ними поднимается целиком и честно говорит, что эфира
  нет. HaLow вообще требует другого пути: это сетевой интерфейс, а не
  «радио с пакетами».
- **Цветной вёрстки.** Цветная панель показывает монохромный кадр
  128×64, увеличенный целым коэффициентом.
