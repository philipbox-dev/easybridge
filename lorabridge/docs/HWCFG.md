# hwcfg — конфигурация железа в рантайме (V2.9)

До V2.9 комбинация «чип + радио + дисплей» фиксировалась на этапе
сборки: под каждую пару нужен был свой бинарник, а «хочу C6 с Ra-02»
означало правку `boards/*.h` и пересборку. Теперь железо описывает
структура `hwcfg_t`, она лежит в NVS, и один образ на чип обслуживает
любую распайку.

## Как это работает

```
NVS (ns "hwcfg", key "blob")
        │  пусто / битая CRC / не проходит проверку
        ▼
профиль сборки (BOARD_PROFILE_ID из boards/*.h)
        │
        ▼
    hwcfg()  ← читают все драйверы при init
```

`hwcfg_init()` вызывается сразу после `nvs_flash_init()` и **до** любых
драйверов. Дальше `radio_registry_init()` выбирает драйвер радио по
`hwcfg()->radio.kind`, `panel_init()` — драйвер дисплея, `touch_init()` —
тача. Пины читаются один раз при инициализации: **смена конфигурации
требует перезагрузки**. Переучивать живое радио на другие пины — верный
способ получить полудохлый чип и невоспроизводимый баг.

Если NVS-запись битая, от другой версии формата или не проходит
валидацию, устройство молча берёт профиль сборки и пишет об этом в лог.
Так неудачный эксперимент с пинами не превращает плату в кирпич.

## Профили

Готовые комбинации живут в таблице `k_profiles[]` в `main/hwcfg.c` —
это **единственный источник правды**. Из неё же скрипт
`tools/gen_profiles.py` генерирует `tools/flasher/web/profiles.json`,
по которому страница прошивки рисует таблицы пинов. Держать схему
подключения второй копией в HTML нельзя: однажды покажет пины от
другой платы.

| Профиль | Чип | Радио | Диапазон | Особенности |
|---|---|---|---|---|
| `s3_e220` | ESP32-S3 | E220 (UART) | 433 | заводская плата, 30 dBm |
| `c6_e220` | ESP32-C6 | E220 (UART) | 433 | |
| `t3_v161` / `t3_v161_915` | ESP32 | SX1276 | 868 / 915 | LilyGO T3, батарея |
| `s3_e22m33s` | ESP32-S3 | SX1268 | 433 | 33 dBm, TCXO |
| `c6_ra02` | ESP32-C6 | SX1278 | 433 | самосбор |
| `s3_ra02` | ESP32-S3 | SX1278 | 433 | самосбор |
| `s3_sx1262_st7789` | ESP32-S3 | SX1262 | 868 | цветной IPS 240×240 |
| `s3_ili9341_touch` | ESP32-S3 | SX1278 | 433 | 320×240 + тач XPT2046 |
| `s3_e28_2g4` | ESP32-S3 | SX1280 | 2.4 ГГц | **драйвер-заглушка** |
| `s3_lora_halow` | ESP32-S3 | SX1262 + HaLow | 868 | **HaLow — заглушка** |

Добавляя профиль, обязательно допишите префикс его id в
`CHIP_BY_PREFIX` в `tools/gen_profiles.py` — иначе генератор упадёт и
не даст забыть, под какой чип он собран.

## Валидатор

`hwcfg_validate()` вызывается и при загрузке из NVS, и перед записью.
Ловит:

- **конфликт пинов** — с оговоркой, что линии одной шины (`SCK`/`MOSI`/
  `MISO`) делить можно, а `CS`/`DC`/`RST`/`IRQ` — нет;
- GPIO, занятый флешем или PSRAM конкретного чипа, и несуществующие
  номера;
- пины «только на вход» (на ESP32 это 34–39) в роли выхода;
- частоту вне диапазона и радио, которое этот диапазон не умеет
  (`hwcfg_radio_supports_band`);
- обязательные пины: `DIO0` для SX127x, `BUSY` для SX126x/SX128x,
  `M0`/`M1`/`AUX` для E220;
- второй SPI-хост на чипах, где он один (C6, C3).

Ошибка возвращается человеческим текстом и уезжает в приложение — там
её видит тот, кто паял.

## Команды BLE

Всё через одну команду `hwcfg`.

```jsonc
// прочитать текущую конфигурацию
{"cmd":"hwcfg"}
→ {"evt":"hwcfg","cfg":{ …полный дескриптор… }}

// список профилей
{"cmd":"hwcfg","action":"profiles"}
→ {"evt":"hwprofiles","list":[{"id":"c6_ra02","name":"C6+Ra-02",
     "radio":"SX127x","band":"433","freq":433125000,
     "display":"SSD1306-I2C","touch":"none","fsk":1}, …]}

// вернуться к профилю сборки
{"cmd":"hwcfg","action":"reset"}
→ {"evt":"hwcfg","applied":true,"reboot":true,"desc":"…"}

// применить профиль целиком
{"cmd":"hwcfg","set":{"profile":"c6_ra02"}}

// точечная правка: патч накатывается на ТЕКУЩУЮ конфигурацию,
// присылать всё целиком не нужно
{"cmd":"hwcfg","set":{"radio":{"pins":{"dio0":21}}}}

// профиль как основа + правки поверх
{"cmd":"hwcfg","set":{"profile":"s3_ra02","radio":{"freq":433500000}}}

→ {"evt":"hwcfg","applied":false,"reboot":false,
   "desc":"GPIO12 занят дважды: radio SCK и disp MOSI"}
```

Поля-виды принимают и число, и имя: `"kind":"SX127x"` и `"kind":2`
равнозначны, имена регистронезависимы. Неизвестные ключи игнорируются.

Калибровка тача — отдельной командой (мастер живёт в приложении,
устройство только принимает результат):

```jsonc
{"cmd":"touch_cal","x0":300,"y0":300,"x1":3800,"y1":3800}
→ {"evt":"touch_cal","saved":true,"reboot":true}
```

`get_radio` теперь тоже отдаёт железо — приложению это нужно, чтобы
знать, показывать ли кнопку звонка:

```jsonc
→ {"evt":"radio","tx_idx":0,"tx_dbm":20,"antenna":"OMNI",
   "chip":"SX127x","band":"868","freq":869525000,"max_dbm":20,
   "fsk":true,"profile":"t3_v161"}
```

## FSK и звонки

Звонки и передача картинок по эфиру идут не LoRa-модуляцией, а GFSK.
Умеет это не каждое радио: у E220 в прозрачном режиме такого доступа
к чипу нет. Поэтому FSK вынесен в отдельный HAL:

```c
const fsk_ops_t *fsk_ops(void);   // NULL, если радио так не умеет
bool fsk_available(void);
```

`ptt.c` и `imgfsk.c` больше не зовут `sx1278_*` напрямую, а
`ptt_supported()` — это ровно `fsk_available()`. На плате без FSK
задача звонков даже не запускается (экономия 6 КБ стека), а попытка
позвонить возвращает:

```jsonc
{"evt":"ptt_state","state":"unsupported","reason":"no_fsk"}
```

Это и есть точка стыковки с веб-звонками (часть 3): для такого
устройства веб — единственный способ говорить.

## Дисплеи

`display.c` рисует интерфейс в монохромный кадр 128×64 — исторический
размер SSD1306, под него сделана вся вёрстка экранов. Панель решает,
как этот кадр показать:

- **SSD1306 / SH1106** (I2C и SPI) — один в один;
- **ST7789 / ILI9341 / ST7735** — раскрашенный в `fg`/`bg` и увеличенный
  целым коэффициентом по центру (на 240×240 это ×3, на 320×240 — ×2).

Коэффициент целый намеренно: дробное масштабирование шрифта 8×16
превращает его в кашу. Полноценная цветная вёрстка — отдельная работа,
не в этой части.

Шину SPI дисплей, тач и радио могут делить: `spi_bus_acquire()`
поднимает хост один раз и засчитывает повторные запросы с теми же
пинами. На C6/C3, где SPI-периферия одна, запрос второго хоста сводится
к первому с предупреждением в логе.
